# 内部测试外包人员管理系统前端产品需求文档

## 1. 产品目标

前端用于支撑内部测试外包人员从注册登录、提交上岗申请、查看审批结果，到领导审批、管理员维护用户和审计操作的完整后台操作流程。页面应体现企业内部工具的特征：信息清晰、操作直接、权限边界明确、便于人工审核和日常管理。

当前前端采用 Thymeleaf + Bootstrap 5 + Bootstrap Icons，不引入 Vue、React 或 Node 构建链。

## 2. 目标用户

| 用户 | 主要目标 | 核心权限 |
| --- | --- | --- |
| 测试外包人员 | 注册账号、登录系统、提交上岗申请、查看个人申请和通知 | 注册、登录、提交申请、查看个人申请、撤回待审批申请、查看本人通知 |
| 上级领导 | 查看待审批申请、通过或驳回申请、批量处理审批 | 登录、查看待审批列表、审批通过、驳回、批量审批、查看通知 |
| 系统管理员 | 管理用户、创建内部账号、分配角色、查看操作日志 | 用户管理、角色分配、查看通知、查看操作日志、访问接口文档 |

## 3. 核心使用场景

1. 外包人员公开注册后自动登录进入工作台，随后提交上岗申请。
2. 外包人员在“上岗申请”页查看申请状态，待审批状态下可撤回申请。
3. 领导登录后进入“领导审批”页，查看待审批申请，执行通过、驳回或批量审批。
4. 管理员在“用户管理”页创建领导、管理员或外包人员账号，并维护用户状态和角色。
5. 用户在“通知消息”页查看申请提交、审批结果等异步通知。
6. 管理员在“操作日志”页按操作人、模块和时间范围查询关键操作记录，辅助审计和问题排查。

## 4. 页面列表与模块结构

| 页面 | 路径 | 目标用户 | 模块结构 |
| --- | --- | --- | --- |
| 登录页 | `/ui/login` | 全部用户 | 品牌区、系统说明、账号登录表单、登录按钮、注册入口、Knife4j 入口、错误提示 |
| 注册页 | `/ui/register` | 测试外包人员 | 品牌区、公开注册说明、注册表单、提交按钮、登录入口、注册成功自动登录反馈 |
| 工作台 | `/ui/dashboard` | 登录用户 | 左侧导航、顶部用户区、页面标题、角色信息、服务健康状态、核心功能快捷入口 |
| 上岗申请 | `/ui/applications` | 测试外包人员 | 个人申请列表、刷新按钮、新建申请按钮、新建申请弹窗、部门下拉、项目下拉、岗位类型、申请原因、撤回操作 |
| 领导审批 | `/ui/approvals` | 上级领导 | 待审批列表、待审批数量、刷新按钮、单条通过、驳回弹窗、全选、批量处理栏、批量意见输入 |
| 用户管理 | `/ui/users` | 系统管理员 | 用户筛选工具栏、用户列表、创建账号弹窗、部门下拉、角色勾选、启用/禁用、角色分配弹窗 |
| 通知消息 | `/ui/notifications` | 登录用户 | 通知列表、通知数量、刷新按钮、事件类型、通知标题、状态、重试次数、创建时间 |
| 操作日志 | `/ui/operation-logs` | 系统管理员 | 筛选工具栏、操作人 ID、模块、开始时间、结束时间、日志列表、请求路径、脱敏参数、操作结果 |
| 接口文档 | `/doc.html` | 开发/审核人员 | Knife4j 接口文档入口，用于人工验证接口参数、权限和返回结构 |

登录后页面统一采用后台壳层：左侧导航、顶部用户区、页面标题区、内容面板、Toast 提示、移动端 offcanvas 导航。

## 5. 视觉风格关键词

- 企业后台
- 克制、清晰、低干扰
- 信息密度适中
- 深色侧边栏
- 白色内容面板
- 青绿色主按钮
- 状态色明确
- 表格优先
- 弹窗承载表单
- Bootstrap Icons 辅助识别

视觉上不做营销式大图、不做复杂动画，不使用过度装饰。按钮、表格、筛选栏、弹窗和状态标签应保持一致风格，方便用户快速扫描和重复操作。

## 6. 关键交互要求

1. 登录态与权限
   - 未登录访问业务页面时跳转登录页。
   - 登录成功后保存 JWT，进入工作台。
   - 退出登录后清除前端 Token，并返回登录页。
   - 根据后端返回权限隐藏无权限菜单和按钮，但后端仍必须做 RBAC 校验。

2. 注册流程
   - 公开注册只面向测试外包人员。
   - 注册成功后自动调用登录接口并进入工作台。
   - 注册失败时在页面展示错误提示，不让用户停留在无反馈状态。

3. 上岗申请
   - 新建申请使用弹窗，避免大表单长期占据页面。
   - 部门和项目使用下拉选择，不允许用户手填 ID。
   - 项目根据所选部门过滤。
   - 只有待审批申请展示“撤回”操作。

4. 领导审批
   - 单条通过直接处理，驳回必须填写审批意见。
   - 批量操作栏只在勾选申请后显示，避免默认干扰。
   - 批量驳回必须填写意见。
   - 处理成功后刷新待审批列表并展示 Toast。

5. 用户管理
   - 用户列表作为主视图，筛选区保持轻量。
   - 创建内部账号使用弹窗，角色必须至少选择一个。
   - 角色分配使用独立弹窗，避免在表格中塞入复杂表单。
   - 用户启用/禁用后刷新列表。

6. 通知与日志
   - 通知、日志类页面以查询和审核为主，不做复杂编辑。
   - 长文本字段需要截断显示，并通过 `title` 支持查看完整内容。
   - 操作结果、通知状态使用状态标签区分。

## 7. 空状态要求

| 页面 | 空状态文案 |
| --- | --- |
| 上岗申请 | 暂无上岗申请 |
| 领导审批 | 暂无待审批申请 |
| 用户管理 | 暂无用户数据 |
| 通知消息 | 暂无通知消息 |
| 操作日志 | 暂无操作日志 |

空状态应显示在表格区域内，包含图标和简短说明。空状态不应让页面塌陷，也不应显示空白表格。

## 8. 加载状态要求

当前页面以接口返回后的 Toast 和表格刷新为主，后续应补充更明确的加载反馈：

- 页面初始化加载：内容区域显示轻量加载提示或表格骨架屏。
- 表格刷新：刷新按钮进入 loading/disabled 状态，避免重复点击。
- 表单提交：提交按钮进入 loading/disabled 状态，防止重复提交申请、重复创建账号或重复审批。
- 接口失败：保留页面原有数据，显示错误 Toast，不直接清空列表。
- 登录失效：自动清除 Token 并跳转登录页，提示“登录已失效”。

## 9. 移动端适配要求

- 断点以 Bootstrap `lg` 为主，桌面端左侧导航常驻，移动端隐藏侧边栏。
- 移动端顶部显示菜单按钮，点击后打开 offcanvas 导航。
- 页面标题区在移动端上下排列，避免按钮和标题挤压。
- 筛选栏在移动端改为单列布局。
- 表格外层必须使用横向滚动容器，避免页面整体横向溢出。
- 弹窗在 390px 左右宽度下应完整显示，表单控件不应超出屏幕。
- 按钮文字不得挤压或换行混乱，必要时使用图标 + 短文本。

## 10. 验收标准

1. 所有页面必须通过 `http://localhost:8080/ui/...` 访问，不能直接打开 Thymeleaf 模板文件。
2. 登录、注册、申请提交、审批处理、用户管理、通知查看和日志查询流程可完成。
3. 无权限用户看不到对应菜单或操作按钮，直接访问接口时由后端拒绝。
4. 表格无数据时展示空状态，有数据时字段清晰、状态明显、操作按钮可识别。
5. 关键操作成功或失败均有 Toast 或页面提示。
6. 桌面端和移动端页面无明显文字重叠、按钮挤压或页面级横向溢出。
7. 前端页面不出现交付阶段类标记，统一呈现为正式系统。
