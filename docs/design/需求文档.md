## 2. 项目背景

当前很多企业在降本增效和业务弹性用工的背景下，会引入测试外包人员参与项目交付。外包人员数量增加后，企业在上岗申请、审批流转、绩效评定、日志留痕和权限管控方面会面临管理成本高、流程不透明、数据分散、追踪困难等问题。

为提升外包人员管理效率，需要建设一套面向企业内部测试外包人员的后台管理系统。系统通过线上化流程覆盖用户管理、上岗申请、日志提交、领导审批、绩效评定等核心场景，使企业可以更精细化地管理外包人员，并提升整体人效。

## 3. 项目目标

本项目目标是通过一个贴近企业真实业务的后台系统，完成从需求分析、数据库设计、后端接口开发、权限控制、缓存设计、接口文档、测试验证到部署交付的完整实践。

业务目标：

- 支持测试外包人员在线注册、登录和提交上岗申请。
- 支持上级领导在线审批上岗申请。
- 支持管理员对用户、角色、权限、绩效和日志进行管理。
- 支持关键操作日志记录，便于审计和问题追踪。
- 支持外包人员绩效等级评定，辅助企业进行人员管理。

技术目标：

- 掌握 Spring Boot 3.x + MyBatis-Plus 的后端开发流程，完成用户、申请、审批、日志、绩效等核心模块接口开发。
- 使用 Maven 管理项目依赖和构建流程，形成规范的 Java 后端工程结构。
- 使用 Lombok 简化实体类、DTO、VO 等对象代码，减少重复 getter、setter 和构造方法。
- 使用 MySQL 8.x 完成规范化数据库设计，设计用户、角色、权限、上岗申请、审批记录、工作日志、绩效记录、操作日志等核心表。
- 使用 Redis 进行登录状态、热点数据或业务锁的缓存设计，提升接口响应速度并降低数据库压力。
- 实践 Controller、Service、Mapper 分层结构，明确接口层、业务层和数据访问层职责。
- 使用 JWT + RBAC 实现用户认证和权限控制，保证不同角色只能访问对应功能。
- 使用 Swagger 3 或 Knife4j 生成接口文档，并使用 Postman 进行前后端接口联调。
- 使用 PageHelper 或 MyBatis-Plus 分页能力，实现用户列表、申请列表、日志列表、绩效列表等分页查询。
- 使用 Log4j2 或 Logback 记录系统运行日志和关键业务日志，便于后续问题排查。
- 使用 Checkstyle 约束代码风格，使代码符合常见 Java 开发规范。
- 使用 JMeter 对登录、申请提交、审批等核心接口进行基础压测，观察接口响应时间和并发表现。
- 前端可使用 Thymeleaf + Bootstrap 5 或 Vue/React + JavaScript/HTML 完成基础页面展示和接口调用。
- 后续可扩展 MQ、Elasticsearch、Prometheus、Grafana、Docker、Spring Cloud Alibaba 等技术，提升项目的异步处理、日志检索、监控部署和企业级工程实践能力。

## 4. 适用对象

本系统主要面向企业内部管理场景，使用对象包括测试外包人员、上级领导和系统管理员。

项目学习对象包括：

- 希望获得第一份后端开发实习机会的同学。
- 对后台开发工程、数据库、缓存、消息队列等基础组件不熟悉，希望通过项目入门的同学。
- 正式面试前希望通过高仿真项目补齐实战经验的同学。

## 5. 用户角色

| 角色 | 角色说明 | 核心权限 |
| --- | --- | --- |
| 测试外包人员 | 需要申请进入项目或岗位的外包测试人员 | 注册、登录、提交上岗申请、查看审批结果、提交工作日志、查看个人绩效 |
| 上级领导 | 负责审核外包人员上岗申请和绩效情况的审批人员 | 查看申请列表、审批通过、驳回申请、查看审批记录、评定或查看绩效 |
| 管理员 | 负责系统基础数据和权限配置的管理人员 | 用户管理、角色管理、权限管理、日志查看、绩效管理、系统配置 |

## 6. 核心业务流程

### 6.1 用户注册登录流程

1. 测试外包人员进入系统注册账号。
2. 系统校验用户名、手机号或邮箱是否重复。
3. 注册成功后，系统默认分配测试外包人员角色。
4. 用户使用账号密码登录系统。
5. 登录成功后，系统生成 JWT Token。
6. 前端后续请求携带 Token 访问系统接口。
7. 系统根据 Token 和用户角色判断接口访问权限。

### 6.2 上岗申请流程

1. 测试外包人员登录系统。
2. 填写上岗申请信息，包括所属部门、项目名称、岗位类型、申请原因等。
3. 提交申请后，申请状态变为待审批。
4. 上级领导查看待审批申请列表。
5. 上级领导查看申请详情，并选择审批通过或驳回。
6. 系统记录审批结果、审批意见和审批时间。
7. 测试外包人员查看申请状态和审批意见。

### 6.3 工作日志提交流程

1. 测试外包人员登录系统。
2. 填写当天工作内容、问题记录、完成情况等日志信息。
3. 系统保存日志，并记录提交时间。
4. 上级领导或管理员可以按人员、日期、项目查询日志。

### 6.4 绩效评定流程

1. 管理员或上级领导进入绩效管理模块。
2. 查询目标外包人员。
3. 根据工作表现设置绩效等级，等级包括 A、B、C。
4. 系统保存绩效记录。
5. 修改绩效时，系统记录修改人、修改时间和修改原因。
6. 关键绩效变更需要写入操作日志。

## 7. 功能需求

### 7.1 用户管理

功能说明：支持系统用户的注册、登录、退出、查询、启用、禁用和角色分配。

主要功能：

- 用户注册。
- 用户登录。
- 用户退出。
- 查询用户列表。
- 查看用户详情。
- 启用或禁用用户。
- 给用户分配角色。

业务规则：

- 用户名不可重复。
- 密码必须加密存储。
- 注册用户默认角色为测试外包人员。
- 被禁用用户不允许登录。
- 不同角色只能访问自己权限范围内的接口。

### 7.2 角色权限管理

功能说明：支持管理员维护系统角色和权限，用于实现 RBAC 权限控制。

主要功能：

- 查询角色列表。
- 新增角色。
- 修改角色。
- 删除角色。
- 查询权限列表。
- 为角色分配权限。

业务规则：

- 系统至少包含管理员、上级领导、测试外包人员三类角色。
- 管理员角色拥有系统全部管理权限。
- 测试外包人员只能操作个人相关数据。
- 上级领导只能审批权限范围内的申请。

### 7.3 上岗申请管理

功能说明：测试外包人员可以提交上岗申请，上级领导可以进行审批。

申请字段：

| 字段 | 说明 |
| --- | --- |
| 申请人 | 当前登录的测试外包人员 |
| 所属部门 | 外包人员申请进入的业务部门 |
| 项目名称 | 申请参与的项目 |
| 岗位类型 | 例如功能测试、自动化测试、性能测试等 |
| 申请原因 | 提交申请的原因说明 |
| 申请状态 | 待审批、已通过、已驳回 |
| 申请时间 | 提交申请的时间 |
| 审批人 | 处理申请的上级领导 |
| 审批意见 | 审批通过或驳回时填写的意见 |
| 审批时间 | 审批处理时间 |

主要功能：

- 新增上岗申请。
- 查询个人申请列表。
- 查询申请详情。
- 撤回待审批申请。
- 上级领导分页查询待审批申请。
- 审批通过申请。
- 驳回申请。

业务规则：

- 同一用户同一项目不允许重复提交待审批申请。
- 只有待审批状态的申请可以被审批。
- 已通过或已驳回的申请不允许重复审批。
- 审批操作必须记录审批人和审批时间。

### 7.4 工作日志管理

功能说明：测试外包人员可以提交工作日志，领导和管理员可以查询日志。

日志字段：

| 字段 | 说明 |
| --- | --- |
| 提交人 | 当前登录用户 |
| 项目名称 | 日志所属项目 |
| 工作日期 | 日志对应的工作日期 |
| 工作内容 | 当天完成的工作 |
| 问题记录 | 遇到的问题或风险 |
| 完成情况 | 已完成、进行中、阻塞 |
| 提交时间 | 系统记录的提交时间 |

主要功能：

- 新增工作日志。
- 修改个人工作日志。
- 查询个人日志列表。
- 按人员、项目、日期查询日志。
- 查看日志详情。

业务规则：

- 测试外包人员只能修改自己的日志。
- 管理员和上级领导可以查看权限范围内的日志。
- 日志提交和修改操作需要记录操作日志。

### 7.5 绩效管理

功能说明：支持管理员或上级领导对测试外包人员进行绩效评定。

绩效等级：

| 等级 | 含义 |
| --- | --- |
| A | 优秀 |
| B | 合格 |
| C | 待改进 |

主要功能：

- 查询绩效列表。
- 查看绩效详情。
- 新增绩效记录。
- 修改绩效等级。
- 查看绩效历史。

业务规则：

- 同一人员同一周期只能有一条当前有效绩效记录。
- 修改绩效需要填写修改原因。
- 绩效修改需要记录操作日志。
- 如使用 Redis 分布式锁，需要防止多人同时修改同一人员绩效导致数据覆盖。

### 7.6 操作日志管理

功能说明：系统需要记录关键业务操作，便于审计、排查问题和后续分析。

日志字段：

| 字段 | 说明 |
| --- | --- |
| 操作人 | 当前登录用户 |
| 操作模块 | 用户管理、上岗申请、工作日志、绩效管理等 |
| 操作类型 | 新增、修改、删除、查询、审批等 |
| 请求接口 | 被访问的后端接口 |
| 请求参数 | 关键请求参数 |
| 操作结果 | 成功或失败 |
| 错误信息 | 操作失败时记录异常信息 |
| 操作时间 | 系统记录时间 |

主要功能：

- 自动记录关键操作。
- 管理员查询操作日志。
- 按用户、模块、时间范围筛选日志。
- 后续可扩展接入 Elasticsearch 进行日志检索。

### 7.7 接口文档管理

功能说明：后端接口需要通过 Swagger 生成接口文档，便于前后端联调和项目验收。

要求：

- 接口路径命名清晰。
- 请求参数说明完整。
- 响应字段说明完整。
- 常见错误码需要说明。
- 接口返回格式统一。

## 8. 非功能需求

### 8.1 安全性

- 用户密码必须加密存储，不允许明文保存。
- 接口访问需要进行 JWT 鉴权。
- 系统需要基于 RBAC 控制不同角色的访问范围。
- 后端需要校验用户输入，避免非法参数进入业务逻辑。
- 敏感操作需要记录操作日志。

### 8.2 性能要求

- 列表查询接口必须支持分页。
- 高频查询数据可以使用 Redis 缓存。
- 审批通知、日志同步等非核心链路可使用 MQ 异步处理。
- 数据库查询需要避免全表扫描，必要字段应建立索引。
- 可使用 JMeter 模拟多人登录、多人提交申请等并发场景。

### 8.3 可维护性

- 项目采用 Controller、Service、Mapper 分层结构。
- 接口统一返回 `ResultVO`。
- 系统需要统一异常处理。
- 常量、枚举、错误码需要集中管理。
- 代码风格遵循阿里巴巴 Java 开发规范。
- 使用 Checkstyle 或类似工具进行代码规范检查。

### 8.4 可扩展性

- 权限模块采用 RBAC 模型，便于后续增加新角色。
- 日志模块预留 Elasticsearch 检索能力。
- 审批通知预留 MQ 异步处理能力。
- 后续可通过 Spring Cloud Alibaba 拆分服务模块，模拟企业级微服务架构。

## 11. 统一响应格式

系统接口统一返回 `ResultVO`，建议结构如下：

```json
{
  "code": 200,
  "message": "success",
  "data": {}
}
```

说明：

- `code` 表示业务状态码。
- `message` 表示响应说明。
- `data` 表示接口返回数据。

## 14. 编码规范要求

### 14.1 命名规范

- 类名使用大驼峰命名，例如 `UserController`、`ApplicationService`、`PerformanceRecord`。
- 方法名使用小驼峰命名，例如 `getUserById`、`submitApplication`、`approveApplication`。
- 变量名使用小驼峰命名，例如 `userId`、`applicationStatus`、`approvalComment`。
- 常量名使用全大写加下划线命名，例如 `MAX_BORROW_DAYS`、`DEFAULT_PAGE_SIZE`、`TOKEN_EXPIRE_TIME`。
- 数据库表名和字段名建议使用小写下划线命名，例如 `sys_user`、`application_record`、`created_time`。

### 14.2 注释规范

- Controller 接口方法需要添加 JavaDoc 或 Swagger 注解，说明接口用途、请求参数和返回结果。
- Service 中复杂业务逻辑需要添加简洁中文注释。
- 涉及权限判断、状态流转、缓存更新、分布式锁、异步处理的代码需要说明关键逻辑。
- 注释应解释业务意图，不应只重复代码含义。

### 14.3 日志规范

- 日志建议统一使用 SLF4J 门面，底层可结合 Logback 或 Log4j2。
- 日志级别需要合理使用，常规流程使用 `info`，调试信息使用 `debug`，异常情况使用 `warn` 或 `error`。
- 日志格式需要统一配置，至少包含时间、日志级别、线程名、类名、方法名和日志内容。
- 关键业务操作需要记录操作人、操作模块、操作类型、操作结果和操作时间。
- 日志中不应输出明文密码、Token 等敏感信息。

## 15. 第一周交付物

第一周需要交付以下内容：

- 需求文档。
- 技术选型说明。
- 系统架构图。
- 数据库 ER 图。
- UML 类图。

其中，需求文档用于明确系统业务边界，技术选型说明用于明确后续开发框架，系统架构图、ER 图和 UML 类图用于支撑第二周进入编码阶段。
